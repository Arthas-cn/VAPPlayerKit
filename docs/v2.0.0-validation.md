纯 SPM 工具宿主不能在真机执行，因此 `SwiftExampleTests` 复用相同测试源码和正式 fixture 作为应用宿主。未删测试、改素材或关闭并发检查。签名证书、描述文件与本地 Team 配置均不进入发布提交。

本轮修复了两个实际运行时问题：

- `AVPlayerItem.status` 的 typed KVO 枚举 `change.newValue` 为 nil，曾使有音轨素材停在 preparing。独立探针与真实音轨先复现，再改读回调对象的 `item.status`；[Swift Foundation 问题记录](https://github.com/swiftlang/swift-corelibs-foundation/issues/3807)。
- 同步析构曾触发 iOS 26.2 的 isolated deinit 运行时崩溃。改为线程安全 owner 移交清理，原同步测试保留并通过；[Swift 官方问题记录](https://github.com/swiftlang/swift/issues/88036)。

UIKit HostingController 回归还实际记录到 `scenePhase=background`、窗口 `activationState=foregroundActive` 及正数 bounds。桥接改由真实窗口场景驱动；修正后的真实宿主与页面 UI 测试均通过。

可复现的测试入口（替换设备 ID 并使用自己的签名）：

```sh
xcodebuild -project Examples/SwiftExample/SwiftExample.xcodeproj \
  -scheme SwiftExample -destination 'platform=iOS,id=<DEVICE_UDID>' \
  -only-testing:SwiftExampleTests test

xcodebuild -project Examples/SwiftExample/SwiftExample.xcodeproj \
  -scheme SwiftExample -destination '<AVAILABLE_UI_DESTINATION>' \
  -only-testing:SwiftExampleUITests/SwiftExampleUITests test
```

范围边界：未人工听验扬声器声音，未做 Instruments 长时间跟踪；上述通过结果不代表这两项。拼接透明视频须显式提供布局，不支持原生 HEVC Alpha 或双文件透明视频。非合作 provider 未退出时排空继续等待；SwiftUI 终态事件不归还文件使用权，需要精确屏障的宿主通过 UIKit `clearAndWait()` 接入。
